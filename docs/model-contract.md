# Model contract

Shared conventions between the data converter, the Blender build, the glb validator, and the web viewer.
If you change anything here, every consumer changes with it. Keep it small.

## 1. Block catalog: `data/blocks.json` (hand-authored)

Array of 13 objects, one per SysML Block that is a clickable car part.

| field | meaning |
|---|---|
| `id` | SysML External ID from the workbook, e.g. `POWERTRAIN`. Also the glTF node name. |
| `name` | Formal SysML block name, e.g. `PowertrainSystem`. |
| `label` | Plain-language name shown to non-engineers. |
| `blurb` | One plain sentence describing the part. |
| `parentId` | Containing block (`VEH` for most; `INVERTER` in `POWERTRAIN`, `BMS` in `ENERGY`, `THERM_CTRL` in `THERMAL`; `VEH` has `null`). |
| `category` | Short grouping word for the UI. |
| `meshName` | Always equals `id`. Kept explicit so no consumer has to assume. |
| `color` | Hex base color used by BOTH the Blender material and the UI chips. Children are lighter tints of their parent. |
| `alpha` | Material opacity. `VEH` is 0.35 (x-ray shell); everything else 1.0. |
| `explode` | Direction vector `[x, y, z]` in glTF space (+Y up, +Z nose, +X car-left) used by the viewer's explode slider. |


Rules:
- **IDs are the workbook External IDs verbatim** (`REQ_SYS_002`, `TC_ACCEL`, `POWERTRAIN`). Requirements also carry `displayId` (`SYS-002`).
- **Direction rule**: `source` is the SysML *client* (dependent end): the satisfying block, the verifying test case, the *derived* requirement, the refining element, the tracing use case, the copy, the allocated use case, the specializing block, the sending block of a flow. `target` is the supplier: the requirement, the parent requirement, the receiving block.
- `relationships` contains every row of the workbook's `All_Relationships` sheet (271). Port-level Assembly/Delegation/ItemFlow rows keep their port ids in `extra` and are lifted to block-level `source`/`target` (port owner blocks).
- `flows` is the derived list of the 9 distinct block-to-block connections (one per connector, ItemFlow rows whose endpoints resolve to two different blocks), used by Blender to build harness tubes and by the viewer to light them.
- Output is deterministic: arrays sorted by id, no timestamps, 2-space indent, trailing newline, UTF-8. Running the converter twice yields identical bytes.
- Unknown `kind` or `type` values must be tolerated by every consumer (ignored, logged once).

## 3. glTF conventions: `dist/car.glb`

- Root node is an empty named `CAR`. Every block is **one mesh object** named exactly its `id`, and all blocks are **flat direct children of `CAR`** (containment lives in `hierarchy`, so a raycast always hits a block-named node).
- Decor meshes (not clickable): `DECOR_canopy`, `DECOR_wheel_FL|FR|RL|RR`, `DECOR_seat_L|R|rear`.
- Flow tubes: `FLOW__<SOURCE>__<TARGET>` (double underscore, because ids contain single underscores).
- Node extras: `sysml_id`, `sysml_kind` (`Block` | `Decor` | `Flow`), `sysml_name`, `sysml_parent`; flows add `sysml_source`, `sysml_target`, `sysml_item`.
- One material per block, named `M_<id>`, base color from `blocks.json`. `VEH` and `DECOR_canopy` export with `alphaMode: BLEND` (alpha on the Principled BSDF Alpha socket); all others `OPAQUE`.
- Coordinate frame: +Y up, **nose points +Z**, +X is the car's left side, meters, origin at ground center under the car. (In Blender: Z up, nose toward -Y, ground at z=0; the exporter's Y-up conversion produces the above.) No Draco or meshopt compression. Under 50 000 triangles.
- No names may carry a Blender `.001` suffix. The validator rejects them.

## 5. Plain-language layer (viewer)

| Formal | Plain (default) |
|---|---|
| Satisfy | "Built into" / on a part card "Responsible for" |
| Verify | "Proven by test" |
| DeriveRequirement (up / down) | "Comes from" / "Leads to" |
| Refine | "Spelled out by" |
| Trace | "Related scenario" |
| Copy | "Copy for the test team" |
| ItemFlow | "Sends" / "Receives" |
| Allocate | "Used in" |
| Block / Requirement / TestCase / UseCase | "Part" / "Requirement" / "Test" / "Scenario" |
