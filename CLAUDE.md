# Project SysML Car

An interactive demo of systems-engineering traceability. A scripted Blender build produces a low-poly x-ray electric car (`dist/car.glb`); a three.js viewer (`web/`) on GitHub Pages lets anyone click a car part or a requirement and see the SysML trace chain (stakeholder need → system requirement → subsystem requirement → part → test).

Live site: https://wallysoftdevlol.github.io/Project-SysML-Car/

## Layout
- `data/source/*.groovy` — the Cameo model script (`modelScript('''<JSON>''')`), the source of truth for `data/model.json`.
- `data/source/*.xlsx` — a derived export of the requirement/relationship subset, kept for cross-checking.
- `data/blocks.json` — hand-authored catalog of the 13 clickable blocks (ids, colors, hierarchy, explode vectors).
- `data/model.json` — generated by `tools/model_script_to_json.py`. Committed. Never hand-edit.
- `docs/model-contract.md` — **read this first.** Naming, schema, coordinate frame, palette shared by every part of the project.
- `model/` — Blender Python (bpy/bmesh). `build_car.py` is the entry point; all numeric placements live in `layout.py`; one module per subsystem in `parts/`.
- `tools/validate_glb.py` — stdlib contract enforcer for the glb.
- `web/` — Vite + TypeScript + three.js viewer. No framework.
- `dist/car.glb`, `dist/build-report.json`, `docs/preview.png` — generated locally, committed.

## Commands (run from repo root)
```powershell
# full local pipeline: convert model script -> build glb with Blender -> validate -> EEVEE preview
.\tools\build_local.ps1
.\tools\build_local.ps1 -CrossCheck   # also diffs against tools/xlsx_to_json.py's output

# pieces
python tools/model_script_to_json.py data/source/Connected_EV_COMPLETE_SYSML_ALL_9_FAMILIES_v7_IMPORT_SAFE.groovy data/blocks.json data/source/Connected_EV_SysML_Requirements_and_Relationships_v7.xlsx data/model.json
python tools/model_script_to_json.py --inspect data/source/Connected_EV_COMPLETE_SYSML_ALL_9_FAMILIES_v7_IMPORT_SAFE.groovy
# tools/xlsx_to_json.py (the workbook converter) is kept callable for cross-checking:
python tools/xlsx_to_json.py data/source/Connected_EV_SysML_Requirements_and_Relationships_v7.xlsx data/blocks.json /tmp/model.xlsx.json
python -m pytest tests -q
& "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python-exit-code 1 --python model/build_car.py -- --data data/model.json --blocks data/blocks.json --out dist/car.glb --report dist/build-report.json --render docs/preview.png --engine eevee
python tools/validate_glb.py dist/car.glb data/model.json data/blocks.json

# web
cd web; npm install; npm run dev        # http://localhost:5173
npm run test:unit; npm run test:e2e; npm run build
```

## Conventions
- glTF node names == block ids. Never let Blender append `.001`.
- Blender must always be run with `--python-exit-code 1`, otherwise script errors exit 0.
- Deterministic outputs: no timestamps or randomness in `model.json` or the glb.
- Plain language first in the UI; formal SysML terms in tooltips or behind the Plain/SysML toggle.
- Local-first: build and test here, push to GitHub at milestones. Pages deploys from `main` via `.github/workflows/pages.yml`.
- Tools: Blender 5.2.1 LTS (Python 3.13 inside Blender), Node 24, Python 3.14 + openpyxl for tools/tests.
